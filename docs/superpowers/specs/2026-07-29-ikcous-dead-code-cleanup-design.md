# IKCOUS Dead Code & Unused Asset Cleanup — Design

## Problem

Running `npx knip` (the dead-code/unused-dependency detector already configured
in this repo) plus a manual cross-reference pass surfaced a set of genuinely
unused files, dependencies, exports, and static assets accumulated over the
project's history (largely from repeated "sync codebase and assets" commits
that copied the whole tree between client instances). None of this is
user-visible — it's repo hygiene, not a bug fix — but it adds noise, wastes
PWA install/precache bytes, and makes the codebase harder to navigate.

A separate investigation into two ambiguous "maybe half-built feature"
findings (`useDataVault` and the forensics logging system) concluded:
`useDataVault` is confirmed-dead (superseded by hand-written equivalent logic
in `StoreContext.tsx`), while the forensics system is a deliberate,
functioning write path (device-local performance logging) whose read/view
side was never built — **the user decided to leave forensics untouched**,
deferring any decision about finishing or removing it to a future,
dedicated design session.

## Scope

**In scope — confirmed dead, remove:**

1. `src/hooks/use-mobile.ts` — unused hook, zero importers anywhere.
2. `dompurify` and `@types/dompurify` — installed, never imported.
3. Six devDependencies with zero references anywhere in the repo (no script,
   no config file, no CI, no docs mention): `@stoplight/spectral-cli`,
   `@stryker-mutator/core`, `ajv`, `license-checker`, `sloc`,
   `type-coverage`.
4. Six unused product photos in `public/images/demo/` (SR Tudo10's old
   catalog: `blusa_manga_longa_lacos.png`, `body_frente_unica_bordo.png`,
   `calca_pezinho_chocolate.png`, `calca_wide_leg_azul_claro.png`,
   `cropped_frente_unica_chocolate.png`, `macacao_frente_unica_bordo.png`)
   — not referenced by any code or database migration.
5. Six unused PWA icon PNG sizes generated by `scripts/generate-app-icons.mjs`
   but never declared in the PWA manifest (`vite.config.ts` only lists
   `icon-192x192.png`, `icon-512x512.png`, `icon-maskable-512x512.png`):
   `icon-72x72.png`, `icon-96x96.png`, `icon-128x128.png`,
   `icon-144x144.png`, `icon-152x152.png`, `icon-384x384.png`. These get
   swept into the service-worker precache regardless of being unlinked
   (via the broad `globPatterns` glob in `vite.config.ts`), so every install
   downloads dead weight. The generation script itself must also stop
   producing them, or they'll silently reappear next time someone re-runs it.
6. Dead/superfluous exports:
   - `triggerHeaderToast` (`src/utils/headerToast.ts`) — only called from
     within the same file; the `export` keyword is unnecessary.
   - `renderBootFailure` (`src/lib/env.ts`) — same pattern, internal-only use.
   - `COLOR_PRESETS` (`src/components/ui/custom/ImageAdjuster.tsx`) — same
     pattern, internal-only use.
   - `cachedReviewsStats` and `cachedQuestionsTotal`
     (`src/utils/admin_cache.ts`) — genuinely write-only: assigned in four
     places, read nowhere (confirmed by full-repo grep). Remove the
     variables and their assignment statements entirely, not just the
     `export` keyword.
   - `prefetchBannersData` (`src/utils/admin_cache.ts`) — fully dead
     function; `AdminLayout.tsx` explicitly stopped calling it (there's a
     comment there: "No longer prefetch coupons, banners, reviews, or QA
     from settings view"). Its private helper `bannersPrefetched` becomes
     unused once the function is removed — remove that too.
   - `useDataVault` (`src/hooks/useDataVault.ts`, the exported function
     spanning roughly lines 191-317) — confirmed dead: `StoreContext.tsx`
     reimplements the same lifecycle by hand (`DataVault.init()`,
     `RealtimeSyncEngine.start()`, `useLeaderElection()` called directly)
     instead of calling this consolidated hook. The sibling export
     `useSyncListener` in the *same file* **is** actively used by
     `StoreContext.tsx` — only the `useDataVault` function itself is
     removed; the file and its other export stay.
7. Four duplicate `export default` statements where the same component is
   already exported by name and every consumer imports it by name (`m.AdminArea`,
   `m.AdminProductsView`, `m.AdminOrdersView`, `m.AdminCouponFormView` — all
   confirmed via grep, no consumer touches the `default` export):
   `src/components/layouts/AdminArea.tsx`,
   `src/views/admin/AdminProductsView.tsx`,
   `src/views/admin/AdminOrdersView.tsx`,
   `src/views/admin/AdminCouponFormView.tsx`. Remove just the redundant
   `export default X;` line from each — keep the named export.
8. Add a `"icons": "node scripts/generate-app-icons.mjs"` entry to
   `package.json`'s `scripts` — this makes the icon-generation script
   discoverable (a deferred minor finding from the earlier icon-fix round)
   and fixes `sharp`/`png-to-ico` being flagged as unused devDependencies by
   knip (knip resolves dependencies referenced from package.json scripts).

**Explicitly out of scope:**
- The forensics logging system (`src/lib/forensicsDB.ts` and its
  integration in `src/hooks/useWebVitals.ts`) — left entirely untouched per
  user decision; revisit as its own design session if ever pursued.
- `@commitlint/cli` and its associated `.commitlintrc.json` — flagged during
  investigation as currently unwired (no git hook invokes it) but clearly
  scaffolded for future use, not presented to or approved by the user for
  removal in this round.
- `pg`, `sharp`, `png-to-ico` — false positives, confirmed used by manual
  `scripts/*.{cjs,mjs}` files, not genuinely unused (sharp/png-to-ico's
  false-positive status is fixed by item 8 above; `pg` remains a tolerated
  false positive since it's used by `scripts/db-*.cjs` files with no
  natural npm-script home).
- `jsr`, `sqlfluff` — false positives, Deno/Python-ecosystem tools outside
  npm's dependency graph.
- `supabase/functions/calculate-shipping/index_test.ts` — false positive, a
  real Deno test file run manually via `deno test`, documented in
  `supabase/setup/`.
- `src/lib/utils.ts`'s `getAvatarGradient()` (rose/pink gradients) and the
  `Header.tsx` "info" toast severity color — both already flagged as
  follow-up tickets from the brand-color-cleanup round, tracked separately.
- Everything else the earlier brand-color-cleanup and app-icon-fix rounds
  already covered.

## Verification

- `npm run typecheck` and `npm run build` must pass after every change (no
  test suite exists in this project).
- `npx knip` should show the 2 "unused files" gone, `dompurify` gone from
  "unused dependencies", the 6 named devDependencies gone from "unused
  devDependencies" (sharp/png-to-ico should also disappear from that list
  once the package.json script is added), the listed "unused exports" gone,
  and the 4 "duplicate exports" gone. Some knip output will remain
  unrelated to this cleanup (e.g. generic shadcn UI re-exports,
  `@commitlint/cli`, forensics exports) — that's expected and out of scope.
- Confirm the app's admin panel still loads correctly after the lazy-import
  default-export removals (`npm run build` succeeding plus a manual smoke
  check of `AdminArea`/`AdminProducts`/`AdminOrders`/`AdminCoupons` routes
  loading is sufficient — this is a lazy-loading wiring change, low risk
  but worth an explicit look since it touches how routes resolve).
