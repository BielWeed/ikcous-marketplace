## Implementação concluída

Não há implementação pendente da X2. O id antes morava em uma variável de módulo consumida uma vez. Agora o card encaminha o id pela navegação, a URL recebe `/admin-devolucoes?id=<id>` e `AdminArea` entrega o parâmetro à tela. A seleção acompanha mudanças de rota. Abrir pela lista atualiza o id e fechar o remove; a confirmação de descarte continua valendo.

Arquivos da implementação:

- `src/App.tsx`: inclui devoluções na serialização de `?id=`.
- `src/components/layouts/AdminArea.tsx`: entrega `selectedDevolucaoId`.
- `src/components/admin/orders/DevolucaoDoPedidoAdminCard.tsx`: passa o id no callback.
- `src/components/admin/orders/OrderDetail.tsx`: propaga o contrato do callback.
- `src/views/admin/AdminOrdersView.tsx`: encaminha o id e mantém o botão geral sem id; não passa o evento de clique como id.
- `src/hooks/useDevolucoesAdmin.ts`: remove a ponte em memória, sem alterar RPCs.
- `src/views/admin/AdminDevolucoesView.tsx`: restaura/sincroniza a seleção e navega ao abrir/fechar.
- `tests/front/devolucao-painel-concluir-estorna.test.tsx`: regressões de id, remontagem, troca, fechamento e recusa do descarte.
- `tests/front/admin-orders-ficha-por-deep-link-nao-remonta.test.tsx`: regressão do botão do cabeçalho.

`App.tsx` e `AdminArea.tsx` receberam uma linha funcional cada. Nenhum layout foi redesenhado.
