1. Retomar a branch publicada acima e ler estas instruções e as fontes vinculadas. Preservar trabalho existente. Conferir a base remota antes da entrega, sem mesclar outras frentes por iniciativa própria.

3. Playwright não está no manifest do app. Se faltar, instalar como ferramenta isolada para não recalcular as dependências do app:

```bash
npm install --prefix .visual/f2/ferramentas-cloud --no-save @playwright/test@1.63.0
mkdir -p node_modules/@playwright
# Só criar os links abaixo se os respectivos destinos ainda não existirem.
ln -s "$PWD/.visual/f2/ferramentas-cloud/node_modules/playwright" node_modules/playwright
ln -s "$PWD/.visual/f2/ferramentas-cloud/node_modules/@playwright/test" node_modules/@playwright/test
```

Usar Chromium já fornecido (por exemplo `/opt/pw-browsers`); não instalar se já disponível. Seguir o README do harness se houver incompatibilidade. Na sessão local, a tentativa `npm install --no-save --package-lock=false` recalculou pacotes e foi interrompida; `npm ci` restaurou tudo. Não repetir essa preparação dentro das dependências principais.

No Node 25, o harness usa `require.resolve("playwright")` e importa a entrada CommonJS, cujo namespace veio sem `chromium`. Um adaptador **local, não versionado**, resolveu usando a entrada ESM oficial, sem editar o harness compartilhado:

```js
// .visual/f2/playwright-esm.mjs, somente se este mesmo problema ocorrer
import { registerHooks } from "node:module";
registerHooks({
  resolve(specifier, context, nextResolve) {
    if (context.conditions.includes("import") && /\/playwright\/index\.js$/.test(specifier)) {
      return nextResolve(specifier.replace(/index\.js$/, "index.mjs"), context);
    }
    return nextResolve(specifier, context);
  },
});
```
